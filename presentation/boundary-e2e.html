Secure remote access
HashiCorp Boundary
Identity-based access, brokered credentials, recorded sessions. SSH, Kubernetes, and just-in-time privilege, end to end, for a regulated bank.
What it is

A smart proxy between people and systems

Identity, not network

Access is granted to a person authenticated against your IdP, not to anyone who can reach an IP.

Nothing is exposed

Targets publish no ports. The only way in is a Boundary session, or no way at all.

Credentials stay hidden

Vault brokers or injects the secret at connect time. With injection the user never sees it.

Every session is visible

Who connected, to what, when, and what they did. Recorded, not reconstructed.

The problem

Standing access is the risk

VPN and bastion sprawl

Flat network reach once you are in. One compromised laptop sees far too much.

Long-lived secrets

Keys and passwords on hosts and in password vaults, rarely rotated, easy to copy.

Who did what?

The host logs a service account. Naming the human means joining CyberArk and host logs and guessing.

Privilege that never ends

Access granted for one change request outlives it by months. Nobody revokes on time.

Concepts

The moving parts

Controller

The control plane. Authenticates, authorizes, tracks sessions. You run it, on Postgres.

Worker

Proxies and records sessions near the targets. Joins the controller by KMS.

Scopes

Global, org, project. Where roles and grants are resolved.

Targets

SSH, TCP, Kubernetes. What a user is authorized to reach.

Host sets

The addresses behind a target, static or dynamically discovered.

Credential stores

Vault or static. Libraries mint or hold the secret for a target.

Auth methods

OIDC, LDAP, password. The human identity every session carries.

Sessions

The audited unit. Bound to a person, a target, and a time.

Architecture

Self-managed, end to end

User

Authenticates through your IdP.

Controller

You run it, on Postgres. Authorizes sessions.

Worker

Proxies, injects, records. Joins by KMS.

Target

SSH host, Postgres, or the cluster.

Vault, alongside

The worker relays credential requests to Vault: SSH certificates and Kubernetes tokens, minted on demand.

Object store, alongside

The worker writes session recordings to S3 or MinIO in BSR format when the session ends.

Audit & compliance

The correlation tax

The host only ever sees the account the credential maps to. Naming the human who sat behind it is a manual join across two systems, done after the fact.
Today

CyberArk session + host auth log + timestamps, reconciled by hand to guess who it was. Slow, and never certain.

With Boundary

The session already names the person, the target, and the time. One record, no join, no guessing.
